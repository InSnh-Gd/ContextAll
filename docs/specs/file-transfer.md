# 文件传输

对应 `session-protocol` 的 `file-transfer`。名额、窗口、位图和命名已有测试。分段长度按帧上限取，见下文。

## 提供和名额

每个对端同时有一个发送名额和一个接收名额。提供的 JSON 含 `transferId`（32 位十六进制）、`streamId`、`totalSize`、`segmentSize`、`segmentCount`、`rootSha256`（64 位十六进制）和 `fileName`。不带逐段哈希。不合规则的提供回复 `FILE_REJECT`，原因 `invalid`，不占名额，流 id 不再使用。

对端还没发完 `{"done":true}` 之前，新的提供是 `busy`。同一对端可以一边发一边收。取消接收不影响发送，也不影响剪贴板。校验和不匹配只删除这一次传输，原因 `checksum-failed`。

一段的长度是 65500 字节，也就是帧载荷上限 65536 减去 4 字节段号和 32 字节 SHA-256。这样一段正文加上前缀仍能放进一帧。

## 位图和窗口

验证过的段写在 `index × segmentSize`，然后才置位。续传只发送未置位的段。发送窗口是 8 段，第 9 段要等确认。位图按 30000 字节的原始切片拆开，`bitOffset` 是字节偏移乘 8。除最后一帧外，标志位 0 表示还有后续。数据等到最后一帧位图到齐才处理。

新的接受先发 `FILE_ACCEPT`，再发一帧空位图，然后才是段。零字节文件在空位图之后完成。

重连时，每个未完成的发送先发 `FILE_RESUME`，最后一帧的 JSON 含 `"done":true`。未知的通告回复 `gone` 并删除。通告之前本地只保留一个发送，第二个是 `busy`。

## 保存

保存前询问默认开启。询问期间占着名额，不写部分文件。询问超过 60 秒就释放名额，原因 `timeout`。

文件名取路径的最后一段，去掉控制字符和 `:*?<>|`。空名、`.`、`..`，以及 `CON`、`PRN`、`AUX`、`NUL`、`COM1`–`COM9`、`LPT1`–`LPT9`（含点号前的主名）改成 `download`。超过 200 个标量时截断。和已有文件重名时，在最后一个扩展名前面插入 ` (2)`。最后改名失败则置 `moveBlocked`，名额继续占着。
